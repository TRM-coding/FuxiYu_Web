# Design

## Context

现有路由按需加载，旧 Apply 与新创建页并存；API 包装器和页面错误辅助共同决定会话反馈。公告编辑器保存 template_id，使模板选择状态与持久内容混杂。动机见 proposal.md。

## Goals / Non-Goals

**Goals:** 保留旧链接可用性并清退旧表单；所有有效身份的业务拒绝均保留会话；草稿保存、重开、发送使用独立内容。

**Non-Goals:** 不重构路由布局、生产启动或分包策略；不修本批以外的公告分页、请求乱序和通用 lint。

## Decisions

1. 旧 Apply 地址重定向现有创建页，按需要保留仍有意义的上下文。删除独立表单；被其他页面消费的资源先核对再处理，避免删除共用样式。
2. API ensureOk 与共享认证错误辅助统一为只有 401 触发全局身份失效；403 保持错误对象、会话与请求现场。保留初始化权限探测的静默 401，避免匿名注册被跳离。
3. 模板选择填入编辑初值，清空选择不清正文；草稿加载恢复快照，不按历史模板 id 重新加载覆盖正文。旧 template_id 仅允许兼容读取，不再作为持久化关联。
4. 恢复失败传完整后端错误对象给现有错误展示层，保留原因和数量。只在受理成功或实际成功的响应分支提示成功。

## Risks / Trade-offs

- 多处页面捕获认证异常，单改包装器仍可能错误跳转 → 同时核对共享辅助及页面调用链，并用代表性 401/403 交互测试验证。
- 重新套用模板可能覆盖已编辑内容 → 草稿加载与模板选择分开触发，重开草稿不自动读取原模板。
- 旧 Apply 样式可能有跨页面消费者 → 查清引用后清退独占资源，保留仍使用的呈现能力。
