# Design

## Context

浏览器采用 HashRouter，业务请求使用站点同源 `/api`，Ctrl 默认启用 HTTPS 并设置 Secure Cookie。构建后的静态文件没有 Vite 开发代理，需要常驻入口同时承担静态服务与 API 转发。

## Goals / Non-Goals

**Goals:** 单个 Node 进程提供 HTTPS、静态产物和同源 API，可由现有 PM2 托管，沿用网络配置及认证契约。

**Non-Goals:** 不增加独立反向代理服务，不改变页面行为或认证策略，不增加 Node WSS 代理。

## Decisions

- 静态服务与 TLS 复用 `http-server`，流式 API 转发复用 `http-proxy`。入口只处理配置和中间件边界；不用开发服务器承载常驻运行，也不自行实现静态文件协议。
- 在静态处理前精确识别 `/api` 与 `/api/`。不使用静态未命中后的全量代理，防止缺失脚本或拼错路径进入 Ctrl。
- 保留原始 API 路径、查询、方法、请求体、状态、Cookie 与多个 Set-Cookie。请求成功、超时或断连均释放计时器与连接；尚未发送响应头时，代理错误使用稳定 JSON 的 502/504，已经发送响应头时关闭连接。
- Web 默认 HTTPS。现有上游自签证书仍使用代理局部的宽松校验，`CTRL_TLS_VERIFY=true` 可开启校验；不使用全局关闭 TLS 校验的变量。
- 配置以脚本位置确定仓库根。`WEB_IP` 只用于生成证书 SAN，监听默认绑定 `0.0.0.0`；已有证书不随配置变化自动替换。
- 静态响应采用保守缓存，入口和资源均不长期缓存。HashRouter 不需要服务端通用 SPA 回退，缺失资源返回 404。

## Risks / Trade-offs

- 自签证书需要客户端信任，SAN 正确不等于自动受信任；README 区分协议错误、地址不匹配与信任错误。
- 上游默认不验证自签证书，兼容现有配置，但不能验证 Ctrl 身份；受信任证书环境可显式开启校验。
- 保守缓存增加重复请求，减少更新后旧资源缓存导致的不一致。
- 原地构建会改动 `dist`，发布不具备原子性；构建成功后才重启，失败时先处理产物状态。

## Migration Plan

安装锁定依赖，确认 Ctrl 地址与 Web 访问 IP，生成或提供证书，完成构建后先前台运行 `npm start` 验证，再用 PM2 启动并保存进程列表。开机恢复须实际执行 `pm2 startup` 输出的系统命令。后续更新遵循构建成功后重启的顺序。
