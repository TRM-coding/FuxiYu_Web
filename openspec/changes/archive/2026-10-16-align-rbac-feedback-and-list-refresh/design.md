# Design

## Context

当前权限矩阵将 manage 排除在方法通配显示之外；Home 的多层错误捕获让失败继续走成功分支；共享刷新指纹只选择少数字段。已删除容器的服务端分页还存在空表移除分页及旧闭包调用风险。

## Goals / Non-Goals

**Goals:** 权限覆盖与后端一致，操作反馈反映成功或受理阶段，业务字段变化能够刷新，异步分页保持用户当前上下文。

**Non-Goals:** 不改变后端授权策略或认证失效策略，不修复其他尚未决策的分页问题，不引入新的运行状态或新的生产托管方式。

## Decisions

1. 矩阵按直接赋予优先，再区分 bypass_auth_entity 覆盖与同域 manage 派生；bypass_resource 保持直接资源能力，不通过方法通配获得。manage 即使方法已覆盖，仍允许非锁定直接配置，因为直接管理权限具有额外资源范围语义。
2. 操作成功必须有可靠确认；受理并非终态。Home 通过既有 pending transition 与轮询跟踪 stopping/restarting 等中间态，失败不移除本地记录或显示成功。
3. 指纹以真实消费者的业务字段为依据，覆盖角色、绑定、硬件、分配及磁盘限额、状态和展示数据。集合顺序无业务意义时归一化，不用采集时间偶然变化掩盖漏字段。
4. 已删除容器动作完成时读取当前分页参数；请求有新旧次序，晚到响应不能覆盖新页。仅权威总数证明越界时回退到有效末页，空表也保留分页组件。
5. 分页审计区分查询上下文变化与普通刷新。机器页解冻后省略页码的独立缺口登记 Q69；其他既有 Q 不重复登记，也不因审计擅自扩大修复范围。

## Risks / Trade-offs

- 指纹字段过少会漏更新、过多会产生无意义更新 → 按实际展示与权限消费者选取并验证单字段变化和集合重排。
- 操作成功响应与运行终态时间不同 → 保留中间态直到心跳给出权威结果，不用成功 toast 替代状态确认。
- 分页回退时总数可能继续改变 → 有限重取并保持可用分页入口，避免自动请求循环。
