## 背景

当前详情页已经从 Ctrl 详情响应读取资源字段与 `bind_mount_path`，但它们仍与镜像身份放在同一张卡片。已删除容器页已经按当前页异步取得逻辑用量，也已经有 `CopyChip` 和可展开行详情，但主表仍单列镜像、Mount 为普通文本，逻辑用量只显示长文本。

本 change 只整理 Web 的已有数据和组件，不改变 Ctrl/Node 协议。逻辑用量是 `du -sb` 的逻辑字节；进度条只在成功样本上显示。页面没有统一的物理磁盘上限可用于百分比时，不伪造精确百分比，仍保留成功条的状态、实际逻辑大小和测量时间。

## 目标与非目标

**目标：**

- 让运行指标区域集中展示 GPU 分配、共享内存和宿主 bind 路径。
- 让已删除页主表只移除镜像列，保留容器、机器、Mount、用量、删除时间、状态和操作；镜像放入展开详情。
- 让用量状态可扫描，保留成功、0 B、pending、error 和不可用的差异；只有成功样本显示进度条。
- 让 Mount 路径在有限列宽内可读且可一键复制。

**非目标：**

- 不增加 API、Node/WSS 回路、数据库列、缓存或新的权限门禁。
- 不改变分页、用量轮询、取消、清理、恢复或快照选择行为。
- 不把逻辑字节改称物理占用，也不从路径字符串推导额外业务事实。

## 设计决策

1. **复用现有响应和组件。** `ContainerDetailPage` 继续使用详情响应中的资源字段和 `CopyChip`；`DeletedContainers` 继续使用 `usageById`、`formatLogicalBytes`、`expandedRowRender` 和现有 Mount 用量 hook。这样避免为纯展示变更扩张接口。

2. **运行指标与镜像身份分离。** 将三项资源字段移动到运行指标的同一字段网格，镜像卡只保留镜像与 Dockerfile。替代方案是保留重复字段或新增“资源详情”接口，前者会造成两个展示口径，后者超出需求，均不采用。

3. **镜像放到展开详情。** 删除主表 image 列，在 `expandedRowRender` 增加镜像字段。替代方案是继续占用固定表格列，无法改善窄屏和长 Mount 的可读性。

4. **Mount 使用小号复制芯片。** 复用已有 `CopyChip` 的复制语义，使用 `meta` + `soft` 小号/弱化样式和完整 `title`；不把路径发送到新的请求层。复制失败沿用组件的已有反馈。

5. **进度条只在成功状态显示。** 逻辑字节成功时复用 `fuxi-nested-child-disk-line` 的文字、track、fill 结构，展示数值和简短测量时间；存在正数比较上限时计算百分比，超出上限时封顶视觉宽度但保留实际数值。没有上限或上限不为正时显示无比例的成功轨道，使用 `aria-valuetext` 说明“已测量，未提供可比上限”，不设置百分比数值。pending、error 和未请求状态沿用主规格既有文字状态，不渲染成功进度条。

## 风险与取舍

- [表格展开详情增加一次点击] → 保留容器名、机器、Mount 和用量在主表，镜像仅移动到详情，不影响主要清理/恢复操作。
- [不同记录没有统一限额] → 成功条在无可靠上限时使用无比例轨道并明确无可比上限，继续显示实际逻辑大小；其他状态沿用既有文字反馈。
- [长路径仍可能超出视觉宽度] → 芯片负责截断视觉文本，`title` 和复制值保留完整路径。
- [移动字段可能破坏现有 CSS 测试] → 以语义文本/角色和现有组件选择器补充回归，不改变 API mock 形状。

## 迁移计划

1. 调整两个页面的 JSX/CSS，复用既有字段、用量工具和复制组件。
2. 增加或更新页面测试，覆盖资源归属、展开镜像、复制完整 Mount、成功进度条/超限/无上限、空值、复制失败和非成功状态边界。
3. 运行受影响的 Vitest 测试与构建；确认没有新增网络请求和 API 变更。
4. 回滚时恢复两个页面的展示结构即可，不涉及数据迁移或服务端回滚。

## 待确认事项

- 本 change 不保留产品决策问题：进度条只在成功状态显示；正数比较上限存在时才显示比例，没有可比上限时显示无比例成功轨道。
