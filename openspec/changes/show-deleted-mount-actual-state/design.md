# Design

## Context

已删除容器页已通过 `useDeletedMountUsage` 对当前页记录发起按路径用量请求，并把结果保存在 `usageById`；`mountUsage` 已有稳定错误码映射、三态校验和轮询生命周期。当前 `isMeasurableDeletedRecord` 把已清理记录排除在请求之外，`renderUsageCell` 也在渲染用量前直接返回“已清理”，因此已有的路径结果无法用于判断清理后的实际状态。恢复/清理按钮门禁只读取列表字段，与用量无关。

## Goals / Non-Goals

**Goals:**

- 让已清理但保留历史路径的记录进入同一批当前页用量请求。
- 用已返回的成功/错误项派生“可能存在残留”“目录不存在”“无权限”，并让桌面表格与移动卡片共用。
- 保持 pending、其他失败和 Node 不可用时的保守展示。
- 保持原有恢复/清理权限、按钮门禁、分页、轮询取消与请求体不变。

**Non-Goals:**

- 不新增 Ctrl/Node 接口、字段、数据库迁移、缓存或 WSS。
- 不把路径写入请求体，不在前端主动探测目录。
- 不把用量结果用于启用/禁用恢复或清理按钮。
- 不改变既有列表、分页、确认弹窗或凭据展示。

## Decisions

1. **扩大可测记录范围，而不是增加专用请求。**
   `isMeasurableDeletedRecord` 改为只要求正整数 `deleted_id` 与非空字符串 `mount_path`；已清理标记不再排除。这样 `useDeletedMountUsage` 的当前页采样、5 秒轮询、120 次预算、取消和旧响应失效全部原样复用，避免为“已清理记录”复制一套异步逻辑。替代方案是单独查询已清理记录，会新增请求路径并分裂状态来源，不采用。

2. **派生状态集中在 `mountUsage` 的纯函数中。**
   新增状态派生函数，输入记录与当前 `usageById` 项，输出状态键与中文文案。优先级为：无路径 → 无挂载；成功且已清理 → 可能存在残留；`not_found` → 目录不存在；`permission_denied` → 无权限；有清理标记 → 已清理；升级清理 → 升级清理；否则 mount 保留。纯函数可被桌面状态列、移动卡片和单元测试复用，避免 JSX 内重复条件。只有成功与两个明确错误码会覆盖列表事实；loading/pending/unavailable/其他错误都回退到列表事实，满足“不能误称”。

3. **用量单元格只负责展示样本。**
   去掉“已清理直接返回”的短路：已清理记录在请求期间显示读取/测量状态，成功时继续使用既有逻辑大小、测量时间、进度条与正数上限规则，错误时使用稳定中文原因。状态列单独显示派生后的挂载实际状态：成功且已清理显示“可能存在残留”，`not_found`/`permission_denied` 显示明确原因。无路径仍在最早分支显示“无挂载”。

4. **错误文案保持稳定码白名单。**
   状态列把 `not_found` 映射为“目录不存在”、`permission_denied` 映射为“无权限”；用量列保留既有错误提示。其他错误码仍使用既有不可用/超时/离线原因，未知文本不回显。仅在 `error` 项携带对应稳定码时使用这两个状态文案，pending 或缺失项不会命中。

5. **按钮门禁保持独立。**
   状态列可以读取 `usageById`，但操作列的 `cleanDisabled`、`restoreDisabled` 和确认回调不改动。已清理记录即使显示“可能存在残留”，仍按原 `cleaned_at`、`data_recoverable`、`snapshot` 等字段决定，避免把“疑似残留”变成可恢复或可重复清理的授权。

## Risks / Trade-offs

- [已清理记录增加当前页请求 ID 数量] → 仍按现有单次 100 个上限与当前页范围分批逻辑；请求体只含 ID，不发送路径。
- [成功但 0 B 是否算残留] → 语义保持“可能存在残留”：成功只证明路径可读取，不推断目录为空或一定存在业务数据；同时展示真实 0 B，不夸大为已占用。
- [旧 Ctrl 缺少统计接口] → 已清理行与普通行一样降级为“统计不可用”，状态列仍回退“已清理”，不误报目录不存在或残留。
- [清理完成后重新采样到旧路径] → 重载列表时旧统计先失效；新请求成功才显示残留，失败或 pending 只保守展示已清理，迟到响应继续按代次丢弃。

## Migration Plan

1. 调整 `mountUsage` 的可测记录判断、错误文案与纯状态派生函数。
2. 调整 `DeletedContainers` 的状态列与用量单元格，复用同一 hook。
3. 更新受影响的桌面、移动、工具函数和集成测试，新增明确状态覆盖。
4. 运行定向 Vitest、相关 ESLint 与 OpenSpec 严格校验；回滚时恢复两个前端文件的判断与展示即可，无数据迁移。
